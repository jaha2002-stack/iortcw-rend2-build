# DarkWolf Android Graphics Lab V01 (experimental)

**Exact requested parent:** GitHub Actions Run [39556894566](https://github.com/jaha2002-stack/iortcw-rend2-build/actions/runs/39556894566), commit `6db34503c1d6353076dc7db137ea204d89cc5953` (Win64 Rend2 3FX Visible V03). The Windows DLL cannot run on Android. This branch reconstructs the parent SOURCE, applies the existing GLES3 Android port, and attempts a native ARM64 build.

**Android donor:** Existing native Android TestLab branch `rend2-android-perf-testlab-v0.1`, whose emulator retail smoke passed in Run 37608794676. These scripts are copied by immutable Git blob SHA, not an unaudited binary.

**Immutable defaults/guards:** `r_dlightmode=2`, `r_forceSun=1` must remain visible in a lab catalog and protected as canonical targets. Existing mobile-port startup defaults explicitly disable many effects; those defaults are *not* a faithful 3FX Graphics Lab preset.

## Android mission briefing screenshot / arrow: targeted root fix (October 22, 2026)

A physical ARM64 phone screenshot showed the RTCW "Dark Secret" mission briefing panel with a tiny bottom-right arrow requiring a tap. This is the original single-player `UIMENU_BRIEFING`, **not** a graphics frame or a simple menu dismissal. Source inspection confirmed RTCW's arrow executes `UI_RunMenuScript("playerstart")`, which sets `g_playerstart=1`, queues `fade 0 0 0 0 3` and closes the menus; the server then performs script `playerstart`, autosave and camera setup. The earlier Android patch wrote `g_playerstart=1` during `CG_INIT` and subsequently swallowed `CG_INGAME_POPUP("briefing")`; this failed to handle the active briefing QVM UI correctly on the real handset.

The fix separates responsibilities: `CG_INIT` merely arms `dw_android_briefing_autostart_pending=1` per load; the client forwards the original briefing popup unchanged; a new Android-source-only patch to `ui_main.c` in the host-built `ui.sp.qvm` consumes that pending flag and executes the ORIGINAL arrow semantics once, then clears menu/UI catcher and unpauses. Each future `CG_INIT` re-arms it for the next map. QVM bytecode does not define `__ANDROID__`, so the patched UI uses the launcher's `dw_android_auto_playerstart=1` runtime guard; Windows production source is never touched. Build validates the patched UI C and the produced QVM's embedded acceptance marker before packaging, plus requires the real UI marker in Android runtime. No screen-coordinate tap, noclip, shader or renderer changes. The phone result still requires an on-device test after installing the new APK; build success alone is not that proof.

## Android WASD and free-camera control fix (October 22, 2026)

Physical device feedback: fullscreen and mission start are confirmed, but onscreen W/A/S/D and camera navigation did not move the player, and typed xyz coordinates were cumbersome. Root cause in the Android port: touch only published button flags to the CL_Frame console command buffer as `+forward`/`-forward`, while `Com_Frame` processes command buffers *before* `CL_Frame`. Short taps could disappear between client frames and older actions were delayed; camera used `SDLActivity.onNativeMouse`, which can be suppressed by `mouseActive` in SDL. New `patch_touch_input.py` (native + Java) preserves native bit flags and latches short taps atomically; it applies movement **directly** to signed `usercmd_t.forwardmove/rightmove` at the `CL_CreateCmd` point after keyboard/mouse input but before finish/encoding. A second JNI hook queues camera deltas and changes `cl.viewangles` on the engine thread with pitch limits. Normal USB/Bluetooth keyboard movement remains additive. Real rendered W/A/S/D buttons now show press highlights; right-side drag controls look. In noclip, JUMP/UP and C/DOWN allow vertical exploration without coordinate teleport. A new Android Graphics Lab menu item documents the control gestures and explicitly explains APPLY/QUERY/EDIT/SAVE/LOAD/RESTART. The source build adds both scripts, a Python selftest, and generated C/JNI source contract checks. PC production source, fullscreen fix, mission autostart, protected Cvars, HDR/Bloom/SSGI/3FX effects remain unchanged. Device-level acceptance still needs installation and in-game move/camera check.
