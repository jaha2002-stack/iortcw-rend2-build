# DarkWolf PCPS V2 — постоянное сохранение правил теней по картам

**Назначение:** экспериментальный пользовательский релиз, не Clean Production.  
**База:** PCPS V1 [#41322232296](https://github.com/jaha2002-stack/iortcw-rend2-build/actions/runs/41322232296) и принятый SAFE Clean [#41297344177](https://github.com/jaha2002-stack/iortcw-rend2-build/actions/runs/41297344177), Texture & Material Fidelity V2 [#41286257713](https://github.com/jaha2002-stack/iortcw-rend2-build/actions/runs/41286257713).

## Новые возможности

PCPS V2 автоматически загружает настройки конкретной BSP-карты при входе в неё и сохраняет каждое изменение теней после команд отключения/восстановления. После выхода из игры, последующего запуска, смены карты и `vid_restart` правила автоматически восстанавливаются. **Не нужно повторно выбирать источник или BSP-поверхность**, чтобы применить уже сохранённую настройку.

В отличие от `wolfconfig.cfg` настройки PCPS хранятся в **отдельных файлах** активной пользовательской директории `fs_homepath/Main`, например:
- `dw_pcps_boss1_a.dat`
- `dw_pcps_boss1_b.dat`

Это две чередующиеся копии: журнал A/B с номером поколения, контрольной суммой и подписью BSP. При повреждении последней записи рендерер пытается загрузить предыдущую проверенную. Формат читаемый человеком, но **не выполняй эти файлы через `/exec`** и не редактируй значения вручную — изменится checksum.

**Разные BAT — разные настройки:** если `RUN_DARKWOLF_SEPTEMBER_FOURWEEK.bat` и `RUN_DARKWOLF_TEXTURE_MATERIAL_FINAL_CLEAN.bat` используют разные `fs_homepath`, файлы сохраняются отдельно. Перенести правила можно, закрыв игру и скопировав **оба** файла `dw_pcps_<имя карты>_a.dat` и `_b.dat` в соответствующую другую папку `Main`.

## Команды

| Команда | Действие |
|---|---|
| `/dw_ps_help` | Полный список |
| `/dw_ps_lights` | Перечисление источников и теневых слотов |
| `/dw_ps_picklight`, `/dw_ps_select N` | Выбор источника |
| `/dw_ps_pickcaster` | Выбор BSP-поверхности прицелом |
| `/dw_ps_light_off` | Отключить тень выбранной лампы и освободить слот; **сохранить** |
| `/dw_ps_light_on` | Восстановить тень лампы; **сохранить** |
| `/dw_ps_caster_off` | Исключить BSP-поверхность для выбранной лампы; **сохранить** |
| `/dw_ps_caster_on` | Восстановить BSP-поверхность; **сохранить** |
| `/dw_ps_info` | Состояние выбранного источника и кастеров |
| **`/dw_ps_file`** | Вывести карту, имена файлов, поколение сохранения |
| **`/dw_ps_save`** | Принудительно сохранить все правила карты |
| **`/dw_ps_reload`** | Повторно загрузить правила с диска (сбросить несохранённое в памяти) |
| **`/dw_ps_reset`** | Сбросить и **навсегда сохранить пустые настройки** только текущей карты |

После успешного изменения выводится `PCPS V2: SAVED`. Если запись не удалась, появится `WRITE VERIFY FAILED` или `NOT updated`. В этом случае эффект может сохраняться только в текущем сеансе.

**Важная разница:** `dw_ps_caster_off` отключает тень определённой поверхности, но не освобождает shadow-slot. Только `dw_ps_light_off` исключает источник из отбора на построение теней. Прямой свет остаётся включённым; бюджет 3 основных теневых слота и два динамических резерва остаётся прежним.

## Защита от ошибочной загрузки

- Ключ карты: имя BSP, размер, количество BSP-поверхностей и подпись материалов/типов/AABB всех world BSP surfaces. После изменения/пересборки BSP старые правила **не применяются**.
- Для caster хранится surface ID только данной карты, shader и AABB; после загрузки восстанавливается указатель на геометрию текущей карты и проверяется целостность. **Глобальных запретов материалов нет**.
- Для лампы сохраняются X/Y/Z источника, radius, sourceClass и StaticPromote fixtureId, не временный dlight index. При неоднозначном соответствии для обычных источников PCPS V1 уже применяет ограничения, не допускающие массового неправильного пропуска.
- Всё применяется только к ordinary point-shadow depth/cubemap: Sun/CSM, Fire/Tesla world mask, другие источники и видимые предметы не отключаются.
- При неверной карте, несовпадении BSP, повреждении файла или ошибочном caster формате — **fail-open**, тени остаются исходными.
- При `vid_restart` и выключении DLL очищается только оперативная память, **не сохранённые правила**. В отличие от этого явный `dw_ps_reset` сохраняет сброшенное состояние.

V2 изменяет лишь интеграцию `SP/code/rend2/tr_main.c` поверх V1. Не меняются шейдеры, HDR16F, Material/Texture Fidelity V2, LUT/CAS/A2C, Sun CSM, Bloom, Volumetric, Fire/Tesla, StaticPromote, EXE и остальные DLL. Адресный Boss1 guard из Clean сохраняется.

## Первый GPU-тест

1. Использовать **отдельную тестовую копию игры**. Сохранить исходную DLL V1 или SAFE Clean.
2. В Boss1 или Factory выбрать лампу: `/dw_ps_picklight` либо `/dw_ps_lights` → `/dw_ps_select N`.
3. `/dw_ps_light_off`: тень пропадает, прямой свет остаётся, слот освобождается. Проверить сообщение `SAVED` и `/dw_ps_file`.
4. Полностью закрыть игру и вновь загрузить ту же карту. Без повторных команд тень должна оставаться отключённой.
5. Выбрать лампу заново, выполнить `/dw_ps_light_on` и перезапустить игру: тень должна вернуться.
6. Аналогично проверить `/dw_ps_pickcaster` → `/dw_ps_caster_off`, перезапуск, затем `/dw_ps_caster_on`. Это проверяет именно BSP-caster, не освобождение слота.
7. Проверить `/vid_restart` и возвращение после посещения другой карты: правила должны автоматически восстановиться.
8. Выполнить `/dw_ps_reset`, закрыть и запустить: старое отключение теней не должно воскреснуть; другие карты сохраняют собственные правила.

## Что ещё НЕ является функцией V2

Это **сохранение настроек инструмента PCPS V1**, а не автоматически физически правильный рендеринг всех теней. Выбор BSP triangle прицелом не гарантирует определения depth-owner большой тени. Model entities и bmodels по-прежнему не выбираются как кастеры; изменения исключения материалов для целой игры отсутствуют.

CI и нативные unit/regression tests проверяют source/file-path и защиту сохранения. **Проверка на пользовательском GPU остаётся обязательной** перед выпуском production.

## Код и доказательства

- `integration/pcps-v1/runtime.inc` — точная V1 runtime база.
- `integration/pcps-v2/persistence.inc` — C-файловый журнал A/B и fail-open parser.
- `integration/pcps-v2/apply.py` — строгая модификация только `tr_main.c` после внедрения V1.
- `integration/pcps-v2/test_native.c` — тест самого C-кода на restart/load/save/corrupt/reset/BSP mismatch.
- `integration/pcps-v2/package.py` — упаковка поверх принятого SAFE Clean #41297344177.
