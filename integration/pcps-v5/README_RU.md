# DarkWolf PCPS V5 — Fire Shadow Path Attribution + Independent Controls

**Дата:** 3 ноября 2026. **Статус:** экспериментальная диагностическая сборка, НЕ Clean Production. База PCPS V4 [#41443968165](https://github.com/jaha2002-stack/iortcw-rend2-build/actions/runs/41443968165), наследующая PCPS V3 [#41435724668](https://github.com/jaha2002-stack/iortcw-rend2-build/actions/runs/41435724668) и принятый SAFE Clean [#41297344177](https://github.com/jaha2002-stack/iortcw-rend2-build/actions/runs/41297344177), Texture & Material Fidelity [#41286257713](https://github.com/jaha2002-stack/iortcw-rend2-build/actions/runs/41286257713).

## Причина разработки — результаты семи факелов Crypt1

PCPS V4 успешно выбирает BSP flame, а `dw_ps_light_off` для него сохраняет **только запрет синтетической FireVol shadow cubemap**. При этом реальный DLight часто обладает **двумя отдельными системами** затенения: обычным point-shadow slot и архитектурной world-occlusion cubemap. В `RB_VolumetricFireV07` реальная point-shadow карта имеет приоритет над синтетической; отключение только synthetic в таком случае ничего не меняет. Ни один из этих путей не может достоверно удалить запечённую световую карту.

**Семь повторных тестов V4 не повторять.** Новая задача — получить проверяемую атрибуцию через код, а не по очереди выключать все факелы.

## Что выводит V5

После выбора факела V5 сообщает:
- Реально используемый получателем FireVol путь: `REAL_DLIGHT_CUBEMAP`, `SYNTHETIC_CACHE`, `FALLBACK` или `NOT_RENDERED` (с маркировкой устаревшего отчёта).
- Наличие конкретного FireVol synthetic hint и живого synthetic cache.
- Состояние обычного `dlightShadowSlot` и отдельного `dlightWorldSlot` связанного DLight.
- Сколько **прошло в геометрию** `drawSurf` и сколько было действительно пропущено по правилам PCPS отдельно для синтетического, обычного point-shadow и world-occlusion-прохода.
- Первые 16 конкретных BSP Surface ID среди обработанных и пропущенных drawSurfs каждого прохода. Это список присутствовавшей геометрии, **НЕ GPU per-pixel depth-owner и НЕ доказательство**, что именно поверхность создала конкретное пятно.
- `BAKED BSP LIGHTMAP: UNKNOWN` — запечённое освещение не распознаётся по одному shadow drawlist.

Счётчик `tessSubmitted` — действительный вызов формирования геометрии поверхности в backend, но не один GPU draw-call/треугольник/пиксель. Ноль при повторном просмотре карты также возможен при reuse уже построенной cache.

## Команды выбора

| Команда | Назначение |
|---|---|
| `/dw_ps_firepick` | Подсмотреть факел под прицелом |
| `/dw_ps_confirm` | Подтвердить BSP пламени |
| `/dw_ps_firelinks` | Перечислить связанные/близкие обычные DLight с временными индексами |
| **`/dw_ps_fire_link N`** | Явно подтвердить связанный с факелом **обычный** DLight из списка. Если источник не fire-tagged, слишком далеко или идентичность неоднозначна — отказ |
| **`/dw_ps_fire_audit_start`** | Обнулить счётчики и начать измерение **только выбранного** факела |
| **`/dw_ps_fire_audit`** | Вывести собранный статус по трём путям |
| **`/dw_ps_fire_audit_save`** | Записать проверенный отчёт в `Main/dw_pcps/<map>_fire_audit.txt` |

Новый аудит ничего не отключает, не создаёт новых GPU-проходов и не меняет lightmap.

## Независимое управление тенью одного источника

| Команда | Какой механизм затрагивает |
|---|---|
| `/dw_ps_fire_synthetic_off/on` | Только **синтетическая FireVol shadow**, как V4 |
| `/dw_ps_fire_point_off/on` | Только обычная **DLight point-shadow cubemap** связанного подтверждённого света. Не удаляет прямой свет; может освободить slot |
| `/dw_ps_fire_world_off/on` | Отдельная **архитектурная DLight World Occlusion** выбранного света. **Только для сравнительного теста!** Выключение может пропускать свет через стены |
| `/dw_ps_fire_synthetic_caster_off/on` | Исключение выбранной BSP из synthetic FireVol capture |
| `/dw_ps_fire_point_caster_off/on` | Исключение BSP из ordinary point-shadow capture связанного DLight |
| `/dw_ps_fire_world_caster_off/on` | Исключение BSP из architectural world-occlusion capture связанного DLight, с invalidation только нужного cache |

Выбор BSP: `/dw_ps_pickcaster`; сначала проверь голубую подсветку поверхности, затем используй команду нужного типа. Отключение **одной поверхности** не освобождает слот. Физический огонь, его прямой свет и видимый материал не удаляются; world-occlusion, однако, участвует в пространственной видимости света, поэтому его выключение может вызвать визуальную утечку.

Все изменения автоматически сохраняются в **старом защищённом формате PCPS V3/V4**: два `Main/dw_pcps/<map>_a.dat` и `_b.dat`, с поколением, checksum и fingerprint BSP. Новый отдельный класс правил 253 используется только для источнико-локальной world-occlusion, существующий класс 254 остаётся за synthetic FireVol. Полного сброса при `vid_restart` нет.

## Первый тест Crypt1: один факел, без повторения семи тестов

1. Тестируй в **отдельной копии игры**; сохрани V4 DLL и пользовательские профили. Чтобы исключить влияние предыдущих семи отключений, сохрани оба файла `crypt1_a.dat`, `crypt1_b.dat` и только затем при необходимости сделай `/dw_ps_reset` в тестовой копии.
2. Наведи прицел на один факел, `/dw_ps_firepick`, `/dw_ps_confirm`, `/dw_ps_firelinks`. В списке выбери **точный DLight**, визуально привязанный к этому факелу, затем `/dw_ps_fire_link N`; не подставляй старый индекс из другого кадра.
3. `/dw_ps_fire_audit_start`; вернись в игру на несколько кадров, затем `/dw_ps_fire_audit_save`.
4. Из отчёта получим, была ли FireVol тень реально `REAL_DLIGHT_CUBEMAP` или `SYNTHETIC_CACHE`, какие две независимые shadow-службы у DLight существуют и сколько геометрии проходит через каждую.
5. Только если по отчёту выбран правильный DLight и есть активная world-occlusion/point-shadow, проверь **по одной** команде для соответствующей компоненты на фиксированной камере. Немедленно восстанови через `_on`.
6. Для тени решётки используй `dw_ps_pickcaster` и правильный отдельный `*_caster_off`. Счётчик `omitted` должен показывать реальное исключение из того захвата; если 0 и cache не перестраивался — нельзя утверждать, что исключение дошло до GPU.

Если после корректного отключения всех активных **динамических** путей тень останется, нужно отдельно сравнить её с baked lightmap (например, в диагностическом `r_lightmap 1`). V5 **не** удаляет запечённую составляющую без BSP/.map данных и не заявляет, что источник lightmap доказан.

## Неизменный контракт

**Нет** новых CVar, шейдеров, глобальных правил по материалам, новых shadow-slots, изменения Fire/Tesla/Volumetric/CSM/Sun, SSGI, Bloom, CAS/LUT/A2C, Texture & Material Fidelity, профилей Quality/High/Ultra/Performance/Balanced или оригинальной отдельной Boss1 поправки. Источники renderer изменены **только** `tr_main.c` и `tr_backend.c` для явных source-local опций и счётчиков. В стандартном состоянии, без пользовательских правил и включённого аудита, исходная графика сохраняется.

**Ограничения:** статическая корреляция огня и DLight не является физически уникальным FixtureId; поэтому используется отдельное подтверждение и отказ при неоднозначности. Переполнение лимита сохранённых правил даёт отказ. Пер-пиксельного GPU shadow-ID в V5 нет. Успешная CI сборка не означает пользовательский GPU PASS.
