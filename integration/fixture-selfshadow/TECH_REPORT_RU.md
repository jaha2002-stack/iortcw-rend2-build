# Технический отчёт · собственная тень ELSS / IFLC

База — утверждённый Production Run `45799720282`, commit `88d667dcfd49e42910209fa9ad11f31a8bd96ebc`, ioRTCW `438e7d413b5f7277187c35b032eb0ef9093ae778`. Базовый ZIP и снимок исходников проверяются по SHA-256 до применения патча. [Production Run](https://github.com/jaha2002-stack/iortcw-rend2-build/actions/runs/45799720282)

## Причина и правка

- **ELSS.** В Production функция `R_ElectricFixtureForCapture` пропускала все неположительные ID у членов группы StaticPromote. Ручная маска сохранялась с отрицательным ID, поэтому в общий point-shadow кубмап попадал корпус. Теперь все участники общей карты должны согласовать явную политику. Синтетический участник может унаследовать её только по подтверждённому `physicalElectricOwnerId`. Для world-only кубмапа результат применяется при поиске в кэше и отрисовке. Без явной политики действует прежний AUTO.
- **IFLC.** `dw_fl_self_pick` брал ближайшую BSP-поверхность без учёта того, участвует ли она в отбрасывании теней. Попадание в полупрозрачное пламя могло остановить выбор до твёрдого корпуса. Ручной выбор IFLC и ELSS теперь пропускает визуальные слои без тени и по-прежнему проверяет геометрию и окклюзию. Для opt-in света IFLC берёт владельца из записи, созданной выбранным профилем. Поиск по координатам раньше мог отклонить ручную политику при совпадении позиций двух записей каталога, хотя был создан один источник.
- Изменены `tr_main.c`, `tr_local.h`, `tr_scene.c`, `tr_elss.inc`, `tr_iflc.inc` и `tr_iflc_self.inc`. Проверка хешей снимка ограничивает изменения этими шестью файлами. Профили и настройки сохраняют прежние форматы. Код распределения ламп и hard ON/OFF на Escape1, шейдеры SunVol, режимы LocalVol 2/3/5, формулы энергии FireVol и бюджеты теней сохранены.

## Проверки и границы

CPU-тест компилирует функции рендерера с синтетическими данными сцены. Проверяются знаковые маски и конфликты владельцев, ручной выбор мимо слоя без тени, сохранение ближайшего препятствия, точный opt-in владелец, область действия фильтра и различие ключей кэша. GitHub Actions связывает GLSL-варианты и собирает Win64 через MinGW-w64. Упаковка сверяет архитектуру и импорты восьми PE-модулей, версии входных файлов и SHA-256 содержимого. Тестовая сборка заменяет только одну DLL в игровом runtime.

Игровые карты и GPU-сцены Windows проверяются на ПК. Ручная маска работает для проверенной геометрии BSP и сохраняет тень при конфликтующих владельцах общей карты. Запечённое освещение и корпуса, представленные отдельной движущейся моделью, находятся вне области ручного BSP-инструмента.
