# IFLC V1: диагностика двух теневых контуров

Отдельный native TestLab для замечания пользователя о кадре
`iflc_flame_1_surface_2992_direct_3.png` из Run #41691075610.
База остаётся Run #41408153237; production-патч IFLC V1 не изменяется.

## Что проверяется

Камера, время клиента, положение и радиус выбранного источника фиксированы.
Проверяются видимость от геометрии карты, обычная cubemap-тень, вклад
нового IFLC Direct и исходного authored DLight №291. В основной матрице
выбранный Volume равен 0; отдельный reference сохраняет Volume=1.
Пара MapLighting baked=0.2/0 проверяет зависимость изображения от lightmap.

Число IFLC `realDlights=1` описывает только выбранного владельца. Оно не
означает отсутствия других источников в сцене. Близкий FireVol anchor
native291 оказался декалью `burnm_01a`; близость декали сама по себе не
доказывает физическую принадлежность native291 выбранному факелу.

## Изоляция диагностических изменений

`prepare.py` сначала восстанавливает и проверяет точный IFLC candidate.
`instrument.py` добавляет camera helpers и три изменённых renderer-файла
только в одноразовое native дерево. Сохраняются patch и SHA256 до/после.
GLSL, алгоритмы выбора и захвата теней, FireVol backend, DLight structs,
позиции и радиусы источников остаются исходными.

Маска `r_iflcShadowAudit` существует только в этой диагностике:

| Бит | Изменение direct receiver pass |
|---:|---|
| 1 | Не применять world visibility выбранного opt-in |
| 2 | Не применять обычную shadow visibility выбранного opt-in |
| 4 | Нулевой RGB-вклад native291 |
| 8 | Нулевой RGB-вклад выбранного opt-in |
| 16 | Не применять world visibility native291 |
| 32 | Не применять обычную shadow visibility native291 |
| 64 | Нулевой RGB-вклад всех DLight |

Целевые источники проверяются по карте, типу/ordinal и точному origin.
Меняются только uniform-параметры двух direct receiver passes; сами
DLight не удаляются и их RGB в структуре не обнуляется. Модельный/объектный
aggregate lighting остаётся исходным, поэтому речь идёт о прямом освещении
поверхностей, а не о полном удалении источника из всех систем.

## Ограничения вывода

Эта сборка не предназначена для установки и не содержит нового Win64
релиза. Выключение visibility — диагностический контроль, а не исправление
теней. Потемнение всего изображения при baked=0 само по себе не доказывает
происхождение малого контура. SSGI сохраняет настройки, но может реагировать
на изменение входного scene color. Результаты кадров требуют ручного
просмотра; успешный CI означает полноту и согласованность эксперимента,
а не визуальную приёмку.
