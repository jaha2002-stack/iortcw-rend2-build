# DarkWolf PCPS V3 — визуальный выбор источника, BSP-подсветка, отдельная папка

Статус: экспериментальный GPU-релиз Windows x64. Основа PCPS V2 #41427487879, SAFE Clean #41297344177 с принятым Texture/Material Fidelity V2 #41286257713.

## Выбор света по прицелу

1. Навести прицел на корпус лампы. Ввести `/dw_ps_picklight`. V3 выполняет raycast по BSP под прицелом и ранжирует до пяти световых источников с учётом угла к origin и геометрической близости к точке BSP-попадания. Выбор пока является ТОЛЬКО предварительным — тень ещё не изменена.
2. На экране появляется панель рангов и цветные номера у проекции световых origin. Оранжевый маркер — текущий кандидат, голубые — альтернативные.
3. При необходимости `/dw_ps_next` или `/dw_ps_prev` для смены кандидата. Команда `/dw_ps_candidates` обновляет список после изменения положения прицела.
4. Выполнить `/dw_ps_confirm` или `/dw_ps_confirm 2`, если выбран кандидат №2 в панели. V3 повторно проверяет точную идентичность origin/class/radius/fixtureId среди текущих источников. При неоднозначном совпадении подтверждение отклоняется. После подтверждения выбранный свет обозначается зелёным.
5. Только теперь можно выполнить `/dw_ps_light_off`, освободить shadow-slot и сохранить. Восстановление `/dw_ps_light_on`. Прямой свет не выключается.

Ранее успешный Factory тест показал lamp index 23 и origin (-96,-952,-203), но dlight index — временный. Если новый подбор предлагает другую лампу, проверяй её origin и не подтверждай неверную. Старые ручные команды `/dw_ps_lights` и `/dw_ps_select 23` по-прежнему работают и выбирают индекс без preview.

`/dw_ps_overlay 0` и `/dw_ps_overlay 1` — включение/выключение только экранных подсказок. Они не меняют тени или профиль. Загрузки BSP на каждом кадре нет: raycast работает только после явной команды.

## Выбор BSP-поверхности

После выбора И ПОДТВЕРЖДЕНИЯ лампы направь прицел непосредственно на стойку лестницы/решётку, а не на её тень. Введи `/dw_ps_pickcaster`. Консоль покажет surface ID, material и ray distance; на экране появится голубая выборочная обводка треугольников этой поверхности. Подсветка основана на самих BSP-вершинах, но для производительности ограничена выборкой до 12 треугольников и не является GPU-depth-owner диагностикой.

Если выделена стена вместо стойки, измени точку обзора и повтори выбор. Затем:
- `/dw_ps_caster_off` — исключить выбранную BSP-поверхность из cubemap выбранного света и автоматически сохранить.
- `/dw_ps_caster_on` — восстановить.
- `/dw_ps_info` — увидеть выбранный свет, исключённые BSP ID и материалы.
- `/dw_ps_file` — показать хранилище, поколение и имена файлов.

Отключение одного caster НЕ освобождает shadow-slot; отключение тени источника через `dw_ps_light_off` освобождает.

## Папка правил и миграция из V2

Все правила PCPS V3 теперь лежат отдельно внутри Main:

`<активный fs_homepath>/Main/dw_pcps/factory_a.dat`  
`<активный fs_homepath>/Main/dw_pcps/factory_b.dat`

Названия для каждой BSP-карты собственные. Формат и A/B-checksum защиты сохранены от V2. Стандартный FS_WriteFile ioRTCW автоматически создаёт вложенную папку.

При **первом** запуске карты V3, если новых файлов для неё ещё нет, программа считывает старые V2 файлы из корня Main (`dw_pcps_factory_a.dat` и `_b.dat`), проверяет BSP hash/checksum, выбирает последнее корректное поколение и записывает в новую папку. Старые оригиналы НЕ удаляются.

Если новая папка уже содержит хотя бы один файл профиля, импорт старого формата запрещён — это предотвращает повторное появление когда-то сброшенных правил. Повреждённые, несовместимые или чужие BSP-правила не применяются. Не сохраняй PCPS в `wolfconfig.cfg` и не выполняй файлы через /exec.

При разных BAT с различными `fs_homepath` правила сохраняются отдельно. Для переноса можно скопировать закрыв игру обе версии файла карты из папки Main/dw_pcps.

## Все новые команды

| Команда | Назначение |
|---|---|
| `dw_ps_picklight` | Ранжировать до 5 источников перед прицелом и показать предварительный выбор |
| `dw_ps_candidates` | Обновить кандидатов |
| `dw_ps_next` / `dw_ps_prev` | Переключать предварительный выбор |
| `dw_ps_confirm [1..5]` | Подтвердить выбранный свет |
| `dw_ps_overlay 0/1` | Скрыть/показать номера ламп и подсветку BSP |
| `dw_ps_pickcaster` | Выбрать BSP и отобразить его геометрию |
| `dw_ps_light_off/on` | Отключить/включить тень лампы с автосохранением |
| `dw_ps_caster_off/on` | Отключить/включить тень отдельной BSP-поверхности с автосохранением |
| `dw_ps_file` | Состояние и пути хранилища |
| `dw_ps_save`, `dw_ps_reload` | Сохранить/перечитать текущую карту |
| `dw_ps_reset` | Постоянно сбросить ВСЕ правила текущей карты |
| `dw_ps_lights`, `dw_ps_select N` | Полный список и ручной точный выбор временного индекса |

## Первый тест Factory

На той же лампе с проверенными координатами (-96,-952,-203): V3 `picklight` → увидеть индекс 23 или координаты этого origin среди кандидатов → при необходимости `next` → `confirm` → `light_off` → проверить сохранение под Main/dw_pcps. Затем `light_on` → `pickcaster` для лестницы → проверить голубой контур → `caster_off`. После выхода и повторного запуска сохранение должно восстановиться.

Отправь скриншот индексов/маркеров и, если не совпадает, полный вывод 5 кандидатов. Не объявлять универсально точную идентификацию светильника без GPU-приёмки.

## Что не менялось

Shadow rendering, Light FixtureId matching, budgets (3 основных плюс 2 динамических резерва), StaticPromote, HDR16F/CSM, Sun/Local Volumetric, Fire/Tesla, SSGI, Bloom, CAS/LUT/A2C, Texture/Material Fidelity V2, shader/GLSL файлы, EXE, остальные DLL, пять производственных CFG. Изменены только tr_main.c и tr_scene.c (постпроцессный 2D overlay). Overlay использует существующие shader assets white и gfx/2d/hudchars.

Ограничения: source picker комбинирует BSP-попадание с динамическими light origins, не осуществляет прямое сопоставление ламп модели/entity с FixtureId; поэтому предварительное подтверждение ОБЯЗАТЕЛЬНО. Подсветка покрывает только world BSP, а не модели/bmodels. GPU-проверка пользователем предстоит.
