# DarkWolf Point Shadow NearWorld / Origin Diagnostic V2 — инструкция

**База:** принятый Clean Production [#41019985033](https://github.com/jaha2002-stack/iortcw-rend2-build/actions/runs/41019985033).  
**Статус:** отдельная тестовая DLL. В существующий Clean Production никакие изменения не вносятся.

## Цель
Не сокращать количество asset Caster/Receiver. Нужна **более правильная форма теней** при сохранении Stage 11. Ранее тест V1 установил, что на Factory (арка/лестница), Crypt1 (подвесной огонь) и прожекторе грубые тени формируют world/BSP фрагменты основной point-shadow cubemap. Путь ProjectDlightTexture не оказался главным виновником.

## Механизмы V2
- `r_dwPointNearWorldClip` 0..32 игровых единиц: в shadowfill fragment shader **только для world BSP** обычного point-shadow при дистанции до точки захвата меньше указанной записывается `discard`. Не удаляются целые объекты и не меняется Stage 11. **Внимание:** при ненулевом радиусе временно возможна утечка света — такой режим только диагностический.
- `r_dwPointOriginAxis` 0 off / 1 X / 2 Y / 3 Z и `r_dwPointOriginShift` -16..16: фиксированный сдвиг мировой точки захвата теневой cubemap, который также передаётся receiver для согласованной выборки. Положение прямого света, яркость и классификация casters не меняются. Допускается иной результат в объёмных эффектах — не production.
- Оставшиеся от V1 `r_dwPointCasterScope`, `r_dwPointReceiverPath` при всех тестах держать **0/0** (весь Caster/Receiver).
- Новые cvars **latched, не архивируются** в штатной конфигурации. Использовать `vid_restart` между режимами.

## Установка
1. Скопировать Clean Production #41019985033 **в отдельную папку**, сохранить original DLL.
2. Заменить только `renderer_sp_rend2_x64.dll` файлом Diagnostic V2; не добавлять тестовые старые GLSL/PK3.
3. Скопировать приложенные `DW_PS_V2_*.cfg` в активную папку `Main`.
4. Загрузить Factory (лестница), затем прожектор, Crypt1 (подвесной огонь). Каждый тест — **в одной и той же точке сохранения**, с теми же освещением, exposure и направлением камеры.

## Режимы (выполнять по одному)
| Режим | Команда в консоли | Цель |
|---|---|---|
| A | `/exec DW_PS_V2_A_ORIGINAL.cfg` | КОНТРОЛЬ: все caster/receiver; без новых изменений |
| B | `/exec DW_PS_V2_B_CLIP_8.cfg` | Только BSP-фрагменты ближе 8 единиц |
| C | `/exec DW_PS_V2_C_CLIP_16.cfg` | То же, 16 единиц |
| D | `/exec DW_PS_V2_D_CLIP_24.cfg` | То же, 24 единицы |
| E | `/exec DW_PS_V2_E_Z_PLUS_4.cfg` | Без clipping, сдвиг shadow origin вверх +4 |
| F | `/exec DW_PS_V2_F_Z_MINUS_4.cfg` | Без clipping, сдвиг origin вниз −4 |
| G | `/exec DW_PS_V2_G_X_PLUS_4.cfg` | Без clipping, сдвиг +4 по мировому X |
| H | `/exec DW_PS_V2_H_Y_PLUS_4.cfg` | Без clipping, сдвиг +4 по мировому Y |

После каждого `exec` выполняется `vid_restart`; проверить активность без аргументов: `/r_dwPointNearWorldClip`, `/r_dwPointOriginAxis`, `/r_dwPointOriginShift`. Не комбинировать B–D и E–H: CFG сами сбрасывают противоположный эксперимент.

## Интерпретация
- Если B/C/D избавляют от толстой тени, смотреть **какой радиус**, сохраняются ли реальные тени, не возникает ли утечек от ближайших стен. Это указывает на ближнюю геометрию BSP, но не доказывает, что следует исключать эти геометрические фрагменты в итоговом рендерере.
- Если E/F (или G/H) улучшают проекции без утечек и смещения shadow-to-light, изучать **устойчивую и физически корректную привязку точки захвата**. Любой постоянный offset должен быть source-aware, а не глобальной ручной настройкой по всем картам.
- Если ничего не меняется: пересмотреть глубину/Bias/receiver/точность кубических граней или соседний свет. Не менять Stage 11 вслепую.
- FPS с одного скриншота — не контролируемый замер; сравнивать в одинаковых местах.

## Возврат к принятому рендереру
```cfg
exec DW_PS_V2_A_ORIGINAL.cfg
```
После проверки **восстановить оригинальную DLL из #41019985033**. Это диагностическая ветка; алгоритм улучшения красивых теней будет выбран только после реальных A/B-снимков B/C/D/E/F/G/H.

**Запрещено включать ограничение Caster Scope или BSP Near Clip в Clean Production.** Нужно сохранить способность максимального количества объектов отбрасывать и принимать тени.
