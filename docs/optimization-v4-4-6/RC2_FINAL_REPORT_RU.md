Отдельная локальная проверка полного дерева обнаружила 3320 остальных побитово одинаковых файлов; это проверка идентичности, а не заявление о построчном ревью каждого из них.

## Дополнительные проверки и ограничения производительности

После старта CI выполнена дополнительная локальная проверка с унаследованными `-O3 -ffast-math`: C-алгоритмы, потоки частиц/следов и SSGI-арифметика совпали с контрольными версиями. В native C++ эмуляции GLSL огня строгая идентичность a==b не сохранилась: 71/200000 примеров различались, максимальная абсолютная разница 5.96046448e-8 (0.660325408 против 0.660325468). Это чувствительность округления дополнительной CPU-эмуляции, не результат GPU и не подтверждение дефекта изображения. Нельзя заявлять побитовое равенство шейдера для всех компиляторов.

Отдельный короткий native микротест сортировки с фактическим 24-байтовым layout drawSurf_t показал преимущество на структурированных и повторяющихся ключах, но НЕ универсальное ускорение. Для 65536 полностью случайных 32-битных ключей два замера RC2 составили 2.45–2.82 мс против 2.31–2.53 мс RC1; диапазоны частично перекрываются. Этот короткий A–B–B–A тест на общей вычислительной среде недостаточен для принятия игрового performance gate. Риск регрессии на высокоэнтропийных больших списках оставлен открытым для реального профиля, а не скрыт. Оптимизация уменьшает обходы, но имеет собственную стоимость записи гистограмм.

Hash-index файлов использует около 20 КиБ дополнительного ограниченного стека и инициализацию buckets; короткие/пустые списки не обязаны ускоряться. Caches добавляют сравнение при меняющихся входах. SSGI ранний выход добавляет ветвления, поэтому итоговый GPU-выигрыш зависит от устройства. По договорённости реальную производительность проверяет пользователь на Windows ПК.

## Бинарники и воспроизводимость

Все пять Win64 SP компонентов пересобраны. qagame/UI совпали между RC1 rebuild и RC2. Renderer, cgame и EXE различаются ожидаемо. Четыре контрольных RC1 DLL совпали с историческим ZIP; контрольный EXE имеет другой hash. Подтверждено изменение встроенного Git version: исторический EXE содержит `33374639-2026-10-14`, контрольный rebuild — `10119255-2026-10-15`, RC2 — `066e52d9-2026-10-15`. Makefile получает идентификатор через git show, поэтому идентичность source tree не равна идентичности timestamp-dependent reconstruct commit. Байтовое совпадение исторического EXE не заявляется.

В обеих Windows build.log по 60 строк compiler warnings; вся историческая база предупреждений не объявляется исправленной. Код не меняет compiler optimization flags ради искусственного результата. ASan/UBSan и тестовые адаптеры не входят в игровые бинарники.
